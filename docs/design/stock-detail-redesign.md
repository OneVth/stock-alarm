# 종목 상세 페이지 재설계

---

## 1. 현재 문제

- 모든 정보가 동일한 시각적 무게로 나열되어 있어 어디를 먼저 봐야 할지 모름
- 기준가, 상승 도달, 하락 도달, 등록일이 동일한 크기의 flex-wrap으로 배치
- 현재가/변동률이 없어서 "지금 이 종목이 어떤 상태인가"를 알 수 없음
- 종목명/코드가 작고, 차트가 중간에 묻혀 있음

---

## 2. 정보 우선순위

| 계층 | 정보 | 사용자 질문 | 시각적 처리 |
|------|------|------------|------------|
| **1차 (Hero)** | 현재가 / 변동률 / 알림 임계값 | "지금 얼마? 도달까지 얼마 남았지?" | 가장 큰 폰트, 색상 강조, 도달 정보 통합, 인라인 편집 |
| **2차 (Primary)** | 가격 차트 | "추세가 어때?" | 넓은 영역, 시선이 자연스럽게 내려가는 위치 |
| **3차 (Tertiary)** | 알림 이력 | "언제 발동했지?" | Collapsible 기본 접힘 |
| **보조** | 메모, 등록일, 상태 | 필요할 때만 확인 | Collapsible 기본 접힘, 작은 텍스트 |

---

## 3. 정보 표시 전략

모든 정보를 동일한 무게로 한 화면에 펼쳐놓으면 정보 과부하가 생긴다. 하지만 탭으로 분리하면 차트를 보면서 알림 설정을 동시에 확인할 수 없는 문제가 생긴다. (실제 증권앱들도 종목 상세는 거의 세로 스크롤 구조를 사용.)

**접근 방식: 계층별 기본 가시성 제어 (Collapsible)**

- 1~2순위 정보 (Hero(현재가 + 알림 설정) + 차트): **항상 펼침**, 첫 화면에서 스크롤 없이 보임
- 3순위 정보 (알림 이력): **기본 접힘**, 섹션 헤더만 보이고 클릭 시 펼침
- 보조 정보 (메모): **기본 접힘**, 섹션 헤더만 보이고 클릭 시 펼침

이렇게 하면 첫 화면에는 Hero(현재가 + 도달 정보) + 차트만 보이고, 페이지가 가볍게 느껴진다. 이력과 메모는 헤더만 보이는 상태라 필요할 때만 펼쳐서 확인.

| 계층 | 기본 상태 | 이유 |
|------|----------|------|
| Hero (현재가 + 알림 설정) | 항상 펼침 | 핵심 정보, 같은 맥락으로 통합 |
| 차트 | 항상 펼침 | 매번 확인하는 핵심 정보 |
| 알림 이력 | 기본 접힘 | 가끔 확인, 테이블이라 면적이 큼 |
| 메모 | 기본 접힘 | 드물게 확인/수정 |

## 4. 계층별 상세 설계

### 4.1 Level 0: 식별 (Identity)

종목명 + 종목코드 + 상태 Badge (토글 가능)

- 페이지 최상단, 뒤로가기 버튼 옆
- 종목명은 중간 크기 (h1이지만 Hero보다는 작게)
- 종목코드는 muted 색상, 종목명 아래 또는 옆
- 상태 Badge는 종목명 옆에 인라인, **클릭 가능**

**상태 토글 동작:**

1. Badge 클릭 → 확인 다이얼로그 ("알림을 비활성화하시겠습니까?" / "알림을 활성화하시겠습니까?")
2. 확인 → `PATCH /api/alerts/[id]/toggle` 호출
3. 성공 → Badge 상태 업데이트 + toast

Badge에 클릭 가능함을 암시하는 시각적 힌트 필요 (cursor-pointer, hover 스타일 등).

**역할:** "내가 지금 어떤 종목을 보고 있는가" 확인 + 알림 상태 빠르게 전환.

### 4.2 Level 1: Hero (현재가 + 알림 설정 통합)

사용자가 이 페이지에 들어와서 가장 먼저 눈에 들어와야 하는 정보.
현재가, 변동률, 기준가, 알림 임계값을 한 영역에서 보여주고 인라인 수정까지 지원.

"기준가 70,000원에서 +10% 올라 77,000원이 도달선인데, 지금 75,000원이니까 2,000원 남았다" — 이 맥락이 한눈에 파악되어야 한다.

**읽기 모드:**

```
75,000원                                    ← text-3xl font-bold (가장 큰 폰트)
+7.14% (+5,000원)                           ← 색상 강조 (success / destructive)
기준 70,000원                                ← text-sm text-muted-foreground
상승 +10% (77,000원) · 하락 -10% (63,000원)   [✏️]
```

- **현재가:** 페이지에서 가장 큰 폰트 (text-3xl)
- **변동률 + 변동액:** 색상으로 상승/하락 구분 (success / destructive)
- **기준가:** muted 작은 텍스트
- **임계값 정보:** 임계값이 먼저, 괄호 안에 도달 가격. 상승은 text-success, 하락은 text-destructive. 중간점(·)으로 구분.
- **편집 버튼(✏️):** 임계값 행 우측, 작은 아이콘

**편집 모드 (✏️ 클릭 후):**

```
75,000원                                    ← 항상 그대로 (편집 불가)
+7.14% (+5,000원)                           ← 항상 그대로

기준가 (원)    [  70,000  ]
상승 (%)      [  10      ]                  [저장] [취소]
하락 (%)      [  10      ]
```

- 현재가와 변동률은 편집 모드에서도 항상 보임 (1순위 정보 유지)
- 기준가 + 임계값만 Input으로 전환
- Input spinner 숨김 CSS 적용
- "저장" → `PUT /api/alerts/[id]` 호출 → 읽기 모드 복귀
- "취소" → 원래 값 복원 → 읽기 모드 복귀
- 등록일: muted 텍스트로 기준가 옆 또는 하단에 포함

### 4.3 Level 2: 가격 차트

Hero 바로 아래, 페이지 전체 너비 사용.

- **기간 탭:** 차트 상단에 30일 / 90일 / 1년 (우측 정렬 또는 좌측)
- **차트 타입 토글:** 라인 / 캔들스틱 전환 (기간 탭 옆 또는 차트 내부)
- **차트 영역:** 높이 400px (모바일 300px), 전체 너비
- **차트 위 수평선:** 기준가(점선) + 상승/하락 도달선(점선)
- **알림 마커:** 차트 위에 발동 시점 표시

**역할:** Hero에서 "지금 얼마"를 확인한 후, "그래서 추세가 어떤데?"로 자연스럽게 시선이 내려옴. 차트는 시각적 면적이 가장 큰 요소이므로 별도의 강조 없이도 시선을 끔.

### 4.4 Level 3: 알림 이력 (Collapsible — 기본 접힘)

**기본 접힘. 카드 없이 구분선(`border-t`)으로 영역 구분.**

- 구분선 위에 Collapsible 헤더: "알림 이력 (N건)" + 펼침/접힘 아이콘 (ChevronDown/Up)
- 접힌 상태에서도 "(N건)" 표시로 이력 유무를 즉시 인지 가능
- 펼치면 **최근 5건** 표시 + 이력이 더 있으면 "더보기" 버튼
- "더보기" 클릭 시 5건씩 추가 로드 (점진적 로드)
- 이력이 없으면: 헤더에 "(0건)" 표시, 펼치면 "알림 이력이 없습니다" placeholder

### 4.5 보조 정보: 메모 (Collapsible — 기본 접힘)

**기본 접힘. 카드 없이 구분선(`border-t`)으로 영역 구분.**
펼쳐진 상태에서 **읽기/편집 모드 전환.**

**읽기 모드 (기본):**

- 메모 내용을 TiptapViewer(읽기 전용)로 렌더링
- 메모가 없으면 "메모가 없습니다" placeholder (muted 텍스트)
- 섹션 헤더 우측에 "수정" 버튼

```
──────────────────────────────────
  메모                    [수정]
  
  - 매수 이유: 반도체 업황 회복
  - 목표가: 85,000원
  (TiptapViewer 읽기 전용 렌더링)
```

**편집 모드 (수정 클릭 후):**

- TiptapEditor 활성화 (툴바 포함)
- "수정" 버튼이 "저장" / "취소" 버튼으로 교체

```
──────────────────────────────────
  메모              [저장] [취소]
  
  [B] [I] [UL] [OL] [링크]
  ┌──────────────────────────┐
  │  (TiptapEditor 편집 가능) │
  └──────────────────────────┘
```

**동작:**

- "수정" → 편집 모드 진입 (현재 메모 내용으로 에디터 초기화)
- "저장" → `PUT /api/alerts/[id]` 호출 → 성공 시 읽기 모드로 복귀
- "취소" → 변경 내용 버리고 읽기 모드로 복귀

**참고:** `TiptapViewer`는 이미 `src/components/editor/tiptap-viewer.tsx`에 구현되어 있음.

### 4.6 보조 정보: 등록일

- Hero 영역 또는 알림 설정 카드 안에 muted 텍스트로 포함
- 별도 섹션 불필요

## 7. 컴포넌트 분리 방향

현재 `stock-detail-client.tsx` 하나에 모든 것이 있으므로, 계층별로 컴포넌트를 분리:

| 계층 | 컴포넌트 | 설명 |
|------|---------|------|
| 식별 | DetailHeader | 뒤로가기 + 종목명 + 코드 + Badge (클릭 시 상태 토글) |
| Hero | StockPriceHero | 현재가 + 변동률 + 기준가 + 도달 정보 + 인라인 편집 (자체 fetch) |
| 차트 | ChartSection | 기간 탭 + 차트 타입 토글 + PriceChart (자체 fetch) |
| 이력 | AlertHistorySection | Collapsible 섹션 (기본 접힘) + 테이블 + 더보기 |
| 메모 | MemoSection | Collapsible 섹션 (기본 접힘) + Viewer ↔ Editor 전환 |

`StockDetailClient`는 이 컴포넌트들을 배치하는 레이아웃 셸 역할만 담당.

## 8. 구현 전략

### Showcase 프로토타입 → 검증 → 실제 적용

1. **Showcase 프로토타입**: `src/app/showcase/prototype/page.tsx`에 더미 데이터로 모든 컴포넌트 UI를 먼저 구현하여 시각적 검증
2. **검증**: 디자인, 계층 구조, Collapsible 동작, 반응형 등을 확인
3. **실제 적용**: 검증된 컴포넌트를 `src/components/stock/`으로 분리하고 실제 상세 페이지에 적용

### Showcase에서 검증할 항목

| 컴포넌트 | 검증 내용 |
|---------|----------|
| DetailHeader | 종목명/코드/Badge 배치, Badge hover 스타일 |
| StockPriceHero | 현재가 폰트 크기, 변동률 색상, 기준가 muted, 도달 정보 표시, 인라인 편집 전환 |
| ChartSection | 기간 탭/차트 타입 토글 배치 (차트 자체는 더미 placeholder) |
| AlertHistorySection | Collapsible 접힘/펼침, "더보기" 버튼 |
| MemoSection | Collapsible 접힘/펼침, 읽기/편집 모드 전환 |
| 전체 레이아웃 | 계층별 시각적 무게, 첫 화면 범위, 모바일 반응형 |
